PART 2: EXPANDING TITLE HOVER ENGINE & 60FPS SMOOTHNESS ARCHITECTURE
================================================================================

2.1  WHY STANDARD CSS HOVER WAS NOT SMOOTH - THE THREE ROOT CAUSES
--------------------------------------------------------------------------------
The naive implementations all fail for measurable reasons:

  (a) THE max-height LIE. Animating `max-height: 1.35rem -> 5.6rem` (90px)
      when a 2-line title is only ~35px tall means the transition curve
      spends its early frames covering the INVISIBLE 35->90px zone:
        - hover-in:  the animation hits a hard ceiling early; the visible
          motion only covers a fraction of the timed curve.
        - hover-out: a ~200ms dead delay while max-height counts down from
          90px to 35px with nothing visibly changing.
  (b) SINGLE-NODE RE-WRAP SNAP. Toggling `white-space: nowrap -> normal` (or
      -webkit-line-clamp) on ONE text element re-wraps on frame 0 - the
      words visibly jump mid-transition. A text node cannot animate between
      two different layout states.
  (c) NORMAL-FLOW GRID REFLOW. Growing the title box in normal document
      flow stretches the height of the entire CSS grid row on hover,
      pushing every card in the rows below down the page - "the page
      jumps". Hover is supposed to be local; this makes it global.

2.2  THE 60fps SILKY-SMOOTH FIX - THREE MOVES
--------------------------------------------------------------------------------
  MOVE A - EXACT PIXEL HEIGHT INTERPOLATION (--title-full-h)
    A hidden, pre-wrapped MEASUREMENT LAYER (.anime-card-title-measure)
    renders the same title with normal white-space at the same width as the
    visible layers. A ResizeObserver + useLayoutEffect records its exact
    rendered height and exposes it as the CSS custom property
    `--title-full-h: 35px` (for example). The expanded layer animates
    `height: 0 -> var(--title-full-h)` - the transition curve is spent
    ENTIRELY on visible motion. `data-multiline="true"` is set only when
    the title actually wraps onto 2+ lines (height > 1.6 x line-height);
    single-line titles remain COMPLETELY STATIC on hover.

  MOVE B - DUAL-LAYER CROSSFADE
    Two sibling layers share identical typography:
      .anime-card-title-collapsed - 1-line `truncate` with ellipsis, fades
                                    out (opacity 0.2s ease)
      .anime-card-title-expanded  - full wrapped text, fades in and glides
                                    translateY(6px) -> 0 over
                                    0.42s cubic-bezier(0.22, 1, 0.36, 1)
    No re-wrap ever happens mid-transition; the eye reads it as one text
    block smoothly unfolding.

  MOVE C - ANCHORED BOTTOM EXPANSION (ZERO GRID REFLOW)
    The parent card (AnimeCard) reserves a FIXED-HEIGHT flow spacer at its
    bottom: `<div class="relative h-[56px] md:h-[60px]">`. The title
    container is anchored inside the card FRAME (which gains `relative`)
    with `position: absolute; bottom: 0; left: 0; right: 0; z-index: 20`.
    On hover the wrapped title grows UPWARD over the poster artwork; the
    spacer never changes height; the grid never reflows; the cards below
    never move. The card frame's `overflow-hidden` clips the expansion at
    the card edge so nothing bleeds outside the card.

  THE THREE STYLES (Settings > Appearance > Hover style)
    stretch = "Fluid Stretch"  : title unfolds in its reserved zone, the
                                 container nudges up 2px (default).
    elevate = "Floating Pill"  : the expanded title sits in a floating
                                 glass pill that lifts 6px above the
                                 poster (border + blur + shadow).
    glow    = "Neon Accent"    : crimson/violet neon text-glow plus a
                                 gradient neon underline that scales
                                 scaleX(0.18) -> scaleX(1).
    All three are PURE CSS keyed on `data-style` - zero JS per frame.

import { useLayoutEffect, useRef, useState, type CSSProperties, type ReactNode } from "react";
import { useSettings, type TitleHoverStyle } from "../hooks/useSettings";

// ─── ExpandingCardTitle — the 60fps Expanding Title Hover engine ──────────
//
// WHY THIS EXISTS (root causes the naive approach died of):
//
//  1. `max-height` transitions lie. Animating max-height 1.35rem → 5.6rem
//     (90px) when a 2-line title is only ~35px tall means the transition
//     curve spends its early frames covering the invisible 35→90px zone:
//     the visible motion starts late on hover-in (hard ceiling hit early is
//     the reverse problem on hover-out — a ~200ms dead delay while
//     max-height counts down 90→35px with nothing visibly changing).
//
//  2. Toggling `white-space: nowrap → normal` (or -webkit-line-clamp) on a
//     SINGLE text node snaps on frame 0 — words jump mid-transition.
//
//  3. Growing the title box in normal flow stretches the whole CSS grid row
//     on hover, pushing every card in the rows below down the page.
//
// THE FIX, in three moves:
//
//  A. EXACT PIXEL HEIGHT INTERPOLATION — a hidden pre-wrapped measurement
//     layer (`.anime-card-title-measure`) records the true multi-line pixel
//     height of the title via ResizeObserver + useLayoutEffect, exposed as
//     `--title-full-h` (e.g. 35px). The expanded layer animates
//     height 0 → var(--title-full-h): the transition curve is spent
//     ENTIRELY on visible motion. data-multiline="true" is set only when
//     the title actually wraps — single-line titles stay 100% static.
//
//  B. DUAL-LAYER CROSSFADE — `.anime-card-title-collapsed` (1-line
//     truncate + ellipsis) fades out while `.anime-card-title-expanded`
//     (wrapped text) fades in with a 6px translateY glide over
//     0.42s cubic-bezier(0.22, 1, 0.36, 1). No re-wrap snap: the two
//     layers share identical typography.
//
//  C. BOTTOM-ANCHORED EXPANSION (zero grid reflow) — the parent card
//     reserves a fixed-height flow spacer (h-[56px] md:h-[60px]) and the
//     title container is position:absolute bottom:0 inside the card frame,
//     so expansion grows UPWARD over the poster artwork. Grid rows below
//     never move.
//
// The three styles (stretch / elevate / glow) are pure CSS keyed on
// data-style — see the .anime-card-title-container blocks in index.css.

interface Props {
  title: string;
  /** Small meta row rendered under the title (score · status · year / EP). */
  meta?: ReactNode;
  /** Force a hover style — used by the Settings live preview cards. */
  styleOverride?: TitleHoverStyle;
  /** White text + drop shadow for titles laid over poster artwork. */
  onArtwork?: boolean;
  className?: string;
}

export function ExpandingCardTitle({ title, meta, styleOverride, onArtwork, className = "" }: Props) {
  const [settings] = useSettings();
  const hoverEnabled = settings.expandingTitleHover;
  const style: TitleHoverStyle = styleOverride ?? settings.activeHoverStyle;

  const measureRef = useRef<HTMLSpanElement>(null);
  const [fullH, setFullH] = useState(0);
  const [multiline, setMultiline] = useState(false);

  // (A) Exact height measurement. The measure layer is absolutely
  //     positioned left-0 right-0 inside the title container, so its width
  //     tracks the container exactly like the visible layers — a
  //     ResizeObserver on it re-measures on card resize (grid columns,
  //     breakpoint flips) with zero layout thrash.
  useLayoutEffect(() => {
    const el = measureRef.current;
    if (!el) return;
    const measure = () => {
      const h = el.getBoundingClientRect().height;
      setFullH(Math.round(h * 100) / 100);
      const lh = parseFloat(getComputedStyle(el).lineHeight) || 18;
      setMultiline(h > lh * 1.6);
    };
    measure();
    const ro = new ResizeObserver(measure);
    ro.observe(el);
    return () => ro.disconnect();
  }, [title]);

  // Setting disabled → render the static legacy title (1-line truncate).
  if (!hoverEnabled) {
    return (
      <div className={`min-w-0 ${onArtwork ? "anime-card-title-onartwork" : ""} ${className}`}>
        <span className="block truncate text-[13px] font-bold leading-snug tracking-tight text-foreground">
          {title}
        </span>
        {meta}
      </div>
    );
  }

  return (
    <div
      className={`anime-card-title-container group/xantitle relative ${onArtwork ? "anime-card-title-onartwork" : ""} ${className}`}
      data-style={style}
      data-multiline={multiline ? "true" : "false"}
    >
      {/* Hidden measurement layer — pre-wrapped, invisible, out of a11y tree */}
      <span
        ref={measureRef}
        aria-hidden="true"
        className="anime-card-title-measure anime-card-title-text absolute left-0 right-0 top-0 invisible pointer-events-none select-none"
      >
        {title}
      </span>

      <span className="relative block">
        {/* Collapsed layer — 1 line, truncate + ellipsis */}
        <span className="anime-card-title-collapsed anime-card-title-text block truncate text-[13px] font-bold leading-snug tracking-tight">
          {title}
        </span>
        {/* Expanded layer — full wrapped text, grows 0 → --title-full-h */}
        <span
          className="anime-card-title-expanded anime-card-title-text block text-[13px] font-bold leading-snug tracking-tight"
          style={{ "--title-full-h": `${fullH}px` } as CSSProperties}
        >
          {title}
        </span>
      </span>

      {meta && <div className="anime-card-title-meta">{meta}</div>}
    </div>
  );
}

BUG 1: HORIZONTAL CAROUSEL HOVER CLIPPING (SECTIONROW)
--------------------------------------------------------------------------------
WHAT WAS WRONG
  Horizontal scroll rows used `overflow-x-auto` with only `pt-2 pb-2`
  headroom. When an AnimeCard lifted on hover (`-translate-y-1.5` = 6px
  upward) and cast its enlarged shadow, the top of the card border and the
  top of the shadow were sliced off by the scroll container's overflow
  boundary: `overflow-x: auto` computes the untouched `overflow-y` to
  `auto` (CSS Overflow L3), so the padding box clips anything painted above
  it. 8px of headroom was still not enough for the ~4px shadow bleed on
  bright backgrounds.

ROOT CAUSE
  Scroll containers clip at the PADDING box edge; the previous padding
  budget under-counted the shadow bleed that comes with the hover lift.

FIX DONE
  Scroll container padding is now `pt-2.5 pb-4 -mt-2.5`: 10px of top
  headroom (6px lift + 4px shadow bleed) and 16px below so the enlarged
  hover shadow is not sliced at the bottom either. `-mt-2.5` compensates
  the top padding so the cards keep their exact original position relative
  to the header - net layout shift: 0. Upward overhang is never scrollable
  overflow, so no vertical scrollbar can appear and horizontal snap/scroll
  is untouched.

BUG 2: HERO CAROUSEL PAGINATION DOT OVERFLOW & MOBILE CONTROL COLLISION (HEROCAROUSEL)
--------------------------------------------------------------------------------
WHAT WAS WRONG
  1) When `items` had up to 20 anime, all 20 pagination dots rendered in an
     unwrapped flex row, colliding with the info column on narrow
     viewports.
  2) On mobile (< 768px) the bottom control clusters sat a few pixels above
     the card bottom edge, overlapping the fixed mobile glass bottom
     navigation bar (height calc(4rem + env(safe-area-inset-bottom))).

ROOT CAUSE
  No cap on slide count + no wrap strategy for the dots; bottom offsets
  never accounted for the fixed bottom nav on small screens.

FIX DONE
  - `slides = anime.slice(0, 8)` caps the carousel at 8 slides.
  - Dots row gains `flex-wrap max-w-[55vw]` so it wraps defensively and
    never crosses the safe zone.
  - Both bottom clusters raised on mobile to `bottom-20` and restored on
    desktop (`md:bottom-7` for dots, `md:bottom-6` for arrows).

BUG 4: REDUCED-MOTION CSS RULE MISSING CUSTOM KEYFRAME CLASSES (INDEX.CSS)
--------------------------------------------------------------------------------
WHAT WAS WRONG
  Enabling "Reduced motion" (html.xan-reduce-motion) or the OS-level

--------------------------------------------------------------------------------
WHAT WAS WRONG
  Navigating away from /watch/:id/:ep while a stream was loading or playing
  left the loading watchdog and the controls auto-hide timer active, left
  fullscreen locked on document.fullscreenElement, and did NOT call

BUG 10: NAN / OVERFLOW PROGRESS BAR WIDTHS ON INVALID DURATION (HISTORY, HOME & ANIMEDETAIL SURFACES)
--------------------------------------------------------------------------------
WHAT WAS WRONG
  If `entry.duration` was 0, NaN, negative or Infinity (malformed history
  entries from older builds, live streams, etc.), the raw progress math
  `Math.round((entry.currentTime / entry.duration) * 100)` produced NaN or
  Infinity, or values > 100% when currentTime slightly exceeded duration -
  rendered as NaN% labels and overflowing progress bars.

ROOT CAUSE
  Each surface had its own local, weaker guard (truthiness check only -
  NaN passes `!duration` but Infinity does not; no clamp of the result).

FIX DONE
  A single shared, hardened helper exported from useSettings.ts:

      export function clampProgressPct(currentTime: number, duration: number): number {
        if (!Number.isFinite(duration) || duration <= 0) return 0;
        if (!Number.isFinite(currentTime) || currentTime <= 0) return 0;
        return Math.min(100, Math.max(0, Math.round((currentTime / duration) * 100)));
      }

  and every progress surface now routes through it: ContinueWatching.tsx
  (the Home page "Airing Today / Continue Watching" cards) and
  CommandMenu.tsx (the command palette's Continue Watching entries). The
  watch-page resume lookup already guarded with `duration > 0`; the helper
  is the canonical implementation everywhere else.

// ─── OPTIONAL LOCAL NODE/EXPRESS SERVER WRAPPER (Part 4) ─────────────────
//
// Runs XANCLD outside Cloudflare Wrangler: plain Node + Express serving the
// built frontend (dist/) and mounting the Hono worker for every /api/* call
// via @hono/node-server's getRequestListener adapter.
//
//   bun run build          # build the frontend to dist/ first
//   bunx tsx server.ts     # or: bun run dev:local
//   → http://localhost:3000
//
// Requires the optional dev deps (see PART 4 of XANCLD_AI_REPLICATION_GUIDE.txt):
//   express, @hono/node-server, tsx, @types/express
//
// Notes:
//  - The worker's c.env.ASSETS is undefined here (BUG 14 FIX guard) — the
//    SPA fallback below serves index.html instead, and /api/* keeps working
//    through the Hono app (CORS proxy + AllAnime crypto resolver).
//  - Worker env vars are provided via a shim so runtimeConfig.ts picks them
//    up; override any of them with the same-named process env var.

import path from "node:path";
import { fileURLToPath } from "node:url";
import express from "express";
import { getRequestListener } from "@hono/node-server";
// @ts-expect-error — the worker is a Cloudflare Worker module; Node runs it
// fine at runtime (it only uses Web-standard APIs + fetch).
import worker from "./src/worker/index";

const __dirname = path.dirname(fileURLToPath(import.meta.url));
const DIST_DIR = path.join(__dirname, "dist");
const PORT = Number(process.env.PORT || 3000);

// Minimal Workers-env shim — mirrors wrangler.toml [vars]. Override via env.
const envShim = {
  ALLANIME_API: process.env.ALLANIME_API ?? "https://api.allanime.day/api",
  MKISSA_ORIGIN: process.env.MKISSA_ORIGIN ?? "https://mkissa.to",
  ZEN_HOST: process.env.ZEN_HOST ?? "https://flixcloud.cc",
  ALLOWED_ORIGINS: process.env.ALLOWED_ORIGINS,
  // ASSETS intentionally ABSENT — exercises the BUG 14 guard path.
};

// Adapter: Node RequestListener wrapping the Hono app's fetch handler.
// `worker` is the Hono instance itself (export default app), whose .fetch
// matches (request, env, executionContext) — exactly what the adapter feeds.
const apiHandler = getRequestListener(worker.fetch, {
  // @ts-expect-error — the adapter accepts an env override payload.
  env: envShim,
});

const app = express();
app.disable("x-powered-by");

// 1) API first — CORS proxy, AllAnime crypto resolver, Zen proxy, health.
// Express 5 removed the '/api/*' wildcard syntax, so we match on req.path
// inside a prefix-free middleware and restore req.originalUrl before handing
// the request to the Hono adapter (Hono needs the full path to route).
app.use((req, res, next) => {
  if (req.path === "/api" || req.path.startsWith("/api/")) {
    req.url = req.originalUrl;
    return apiHandler(req, res);
  }
  next();
});

// 2) Built frontend assets (hashed /assets/*, logo.svg, placeholder.svg…)
app.use(express.static(DIST_DIR, { index: "index.html", maxAge: "1h" }));

// 3) SPA fallback — client-side router handles /anime/:id, /watch/:id, etc.
// (Express 5: no more app.get('*') — a terminal middleware does the job.)
app.use((req, res) => {
  if (req.method !== "GET" && req.method !== "HEAD") {
    res.status(405).json({ error: "Method not allowed" });
    return;
  }
  res.sendFile(path.join(DIST_DIR, "index.html"));
});

app.listen(PORT, () => {
  console.log(`[XANCLD] Local server ready → http://localhost:${PORT}`);
  console.log(`[XANCLD] Serving ${DIST_DIR} + Hono worker API on /api/*`);
});
